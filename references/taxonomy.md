# 受控领域分类树（taxonomy）

> 领域分类回答「这段内容属于什么**领域**」，它和卡片 `kind`（method/fact/decision/lesson/resource，
> 按**知识性质**分）正交、并存，不要混为一谈。
> 浓缩时给每个**主题段（threads[]）**、**每张卡片（cards[].categories）**、**每个会话（categories）**
> 标注领域；取值必须是下方清单里的 `一级/二级`，**可多属**（同时涉及多个领域就列多个）。

## 使用规则

1. **优先复用**已有 `一级/二级`，不为同一领域造近义词：已有「技术开发/开发环境」就不要再写「技术开发/环境配置」。
2. 确无合适的**二级**：挂到最贴近的一级下新增二级。命名用紧凑标识——中英文之间不空格、整体不含空格
   （它会被用作 Obsidian 嵌套标签，标签不允许空格），如 `机器人与Agent/Agent架构与可信执行`。
3. 连**一级**都不匹配：可新增一级，但必须在交付说明里单列「本次新增分类」，经用户确认后回填本文件。
4. `render_notes.py` 会校验：不是恰好两级、或不在本清单的分类，会进报告的 `new_categories` 与 `warnings`。
5. 分类是**稳定标识**，定了不要随意改名（改名等于把历史聚合拆散）；展示时的中英文留空由脚本自动处理。

## 领域树（当前版本，覆盖现有 20 个会话）

### 技术开发
- `技术开发/开发环境` —— 本机环境隔离、容器、远程开发、云 IDE（OrbStack / Docker / Remote-SSH）
- `技术开发/工程部署` —— 项目部署、断点续跑、服务恢复、项目解读与搭建
- `技术开发/排错调试` —— 报错排查、权限 / 403、环境异常
- `技术开发/硬件与设备` —— GPU、设备配置、安装路径等本机设备问题

### 机器人与Agent
- `机器人与Agent/强化学习与Sim-to-Real` —— RL、sim-real、Harness 同构、MockReal、纯仿真边界
- `机器人与Agent/Agent架构与可信执行` —— Agent 架构、安全与可验证、执行外壳、能力契约
- `机器人与Agent/模型与框架` —— 开源模型 / 框架的使用（如 deepseek-harness）

### AI协作方法
- `AI协作方法/提示词与语言效率` —— 用什么语言与模型沟通、提效技巧
- `AI协作方法/Skill设计与复用` —— 设计、迭代、复用 Skill
- `AI协作方法/协作边界` —— 授权边界、何时该先问、人机分工

### 知识管理
- `知识管理/Obsidian方法论` —— 库结构、MOC、双链、Bases、Canvas
- `知识管理/版本与备份` —— Git 备份、多端同步、版本管理
- `知识管理/会话沉淀` —— 对话浓缩、知识蒸馏工作流

### 产品与设计
- `产品与设计/苹果设计研究` —— 苹果设计哲学、设计语言、设计组织
- `产品与设计/设计方法论` —— 通用设计方法与原则
- `产品与设计/产品分析与评审` —— 产品 / 方案评审、可行性判断

### 内容创作
- `内容创作/视频与运镜` —— 视频片段蒸馏、运镜分析、AI 视频复刻

### 职业与发展
- `职业与发展/简历与求职`
- `职业与发展/创业与商业` —— 创业条件、商业模式、下沉策略、需求真伪验证
- `职业与发展/个人复盘` —— 回顾近期工作、自我梳理
