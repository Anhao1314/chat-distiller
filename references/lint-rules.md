# 体检规则（T3：需要判断力的那部分）

> `scripts/lint_notes.py` 承担前两档：**T1 结构一致性**和 **T2 证据核验**——都是机械检查，
> 脚本自己跑。本文件是 **T3**：必须由 agent 读内容才能判断的检查项。
>
> 触发语：「体检知识库」「检查矛盾 / 过期结论」「lint 一下」。

## 首要规则：只报告，不修改

T3 的所有发现都**只报给用户，不要自己动手改**。理由有两条：

1. 这些判断本身有模糊地带——两张卡片「矛盾」可能只是视角不同，机器不该替人拍板。
2. **渲染是从 `distill.json` 全量重建的，直接改 vault 里的 md 会被下次渲染覆盖。**
   真要修改，改的是 `distill.json`（卡片加 `status`/`superseded_by` 字段），再重跑渲染。

所以报告要写成「问题 + 建议动作 + 需要改哪个字段」，让用户点头后再动手。

## 检查流程

1. 先读 `知识索引.md`（**不要**一上来就遍历全部卡片——那正是索引要解决的问题）。
2. 按下面的检查项定位可疑对象，再打开具体卡片和会话笔记核实。
3. 输出一份简报：每条 = 问题类型 + 涉及笔记 + 一句话说明 + 建议动作。

## 检查项

### 1. 结论互相矛盾

两张卡片对同一件事给出冲突的判断，且都没标 `有争议`。

**怎么找**：在索引里找同一领域、主题相近的卡片成对读；特别注意 `decision` 与
`lesson` 两类——它们最常打架（「应该做 A」vs「A 不可行」）。

**报什么**：两张卡片的编号、冲突点一句话、建议（哪张该标 `有争议`，或哪张该改）。

### 2. 过期未标注

较新的会话已经推翻了旧卡片的结论，但旧卡片仍是 `status: 现行`。

**怎么找**：按日期排序比较同一领域的卡片，看新卡是否实质取代了旧卡。

**报什么**：旧卡片编号、取代它的新结论、建议把旧卡改成
`status: 已过期` 并补 `superseded_by: <新卡片编号 - 标题>`。

**注意**：这是本项目最要紧的一项。卡片是给 agent 检索用的，**一条过期的决策留在库里，
agent 会直接照着它行动。**

### 3. 该标未标 / 标错

- 卡片内容里已经写着「此方案已废弃」「后来改成 X」，但 `status` 还是「现行」
- 标了「已过期」却没写 `superseded_by`（脚本 T1 会查这一条）
- 标了「有争议」但正文里看不出争议双方各是什么

### 4. 缺失交叉引用

两张卡片明显相关（同一项目、同一方法的不同侧面），却互不引用。

**报什么**：建议在哪张卡的 `related` 里加上哪张。不要直接加。

### 5. 孤儿卡片

没有任何其他卡片或会话笔记指向它，且它也不引用别人——多半是孤立的一次性记录。

**注意**：孤儿不一定是坏事（有些结论本来就独立）。报告它，但说明「可能合理」。

### 6. 反复出现却没有卡片的主题

同一个概念在三四篇会话笔记里出现，却始终没有一张自己的卡片。

**报什么**：概念名 + 它出现在哪几篇 + 建议抽成一张什么 `kind` 的卡片。

### 7. 粒度失当

- **过细**：把一次性细节（某次操作的具体参数、某台机器的临时路径）抽成了卡片。
  这类内容应该在会话笔记的 `key_points` 里，不该占一张卡。
- **过粗**：一张卡片塞了三四个互相独立的结论，导致它没法被单独检索和引用。

**报什么**：卡片编号 + 属于哪种 + 建议（降级回笔记，或拆成几张）。

### 8. 遗漏的结论

会话笔记里有一句明显可复用的结论，却没被抽成卡片。

**注意**：这一项容易过度报告。只在结论确实「脱离原对话仍能独立成立、
且以后大概率会再用到」时才提。

## 报告格式

```
体检结果（T3 判断项）

1. [过期未标注] C03「本地装依赖比容器省事」
   —— S09（2026-08-20）已改成先用容器隔离再决定，该结论实质被取代。
   建议：把 C03 改为 status: 已过期，superseded_by: C14 - 容器优先的取舍标准。

2. [矛盾] C12 与 C18 对「是否该用云 IDE」给出相反结论，两张都标着现行。
   建议：核实后择一标为「有争议」，或在两卡间加 related 并说明分歧。

共 2 项。要我按建议修改 distill.json 并重跑渲染吗？
```

## 与另外两档的关系

| 档位 | 谁执行 | 典型项 | 能否自动修 |
| --- | --- | --- | --- |
| T1 结构一致性 | `lint_notes.py` | 编号空洞、字段缺失、反链断裂、索引不一致 | 重跑渲染即可 |
| T2 证据核验 | `lint_notes.py` | 日期/数字/版本号/路径在转录中找不到 | 否，需判断 |
| T3 判断项 | **agent（本文件）** | 矛盾、过期、交叉引用、粒度 | 否，只报告 |

建议节奏：T1/T2 每次摄入后顺手跑；T3 每隔一段时间、或摄入了一批新会话之后跑一次。
